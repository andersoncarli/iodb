# [1.1] DB reativo: db.js, node.js, models, adapters (file/yaml/json/sqlite/dash)

O motor de armazenamento reativo em si: `DB()`, `node()` e os adapters pluga­veis (file/blob/dash/jsonl/yaml/json/env/sqlite), com chaves derivadas via LRM.

## Objetivo

Motor de armazenamento reativo: `DB()` (factory polimorfica — arquivo direto,
nome de colecao, ou namespace) e `node()` (resolvedor universal de endereco a
Collection), com adapters plugaveis para file/lines/blob, dash, jsonl, yaml,
json, env, sqlite, e um bus de transicao (`60-transition.js`) para eventos
reativos. Chaves de registro derivadas via LRM (`hash.js`): `key = sha64(payload)
XOR sha64(prevKey)`, verificavel sem back-pointers.

## Linhagem

Este subsistema nasceu como `io/` no projeto `bot` (FRM — Fractal Reasoning
Machine), Sprint 10 ("IO Store Foundation & Architecture"). Foi unificado para
dentro de `bot/lib/adapters/` no "CHECKPOINT io->lib unification", e o `io/`
legado standalone foi arquivado. Em `bot/`, correspondia a feature `1.5` (DB:
db.js, models, adapters), 🟢 avaliada, com garantia de 1 validacao registrada
(2026-08-03).

Extraido para repositorio proprio (`github.com/andersoncarli/iodb`) via
`git subtree split --prefix=lib/adapters`, preservando os 22 commits de
historico relevantes (do commit "Migration Complete: Unified Reactive IO
Architecture Verified" em diante), no mesmo padrao ja usado para extrair
`utils/` e `utest/` do mesmo `bot/`.

Correcao de topologia (2026-09-05): a primeira versao empacotada trazia
`utils/` e `utest/` como git submodules **aninhados dentro de** `iodb/`, o
que fazia a propria suite de `iodb` varrer e rodar todos os testes internos
desses dois projetos (dezenas de arquivos sem nenhuma relacao com io/db).
Corrigido para `iodb` depender de `utils/` (bus, Emitter) e `utest/` (test
runner) como **peers de workspace** — diretorios irmaos no filesystem,
nunca submodule proprio nem vendorizado. `iodb` importa `../utils/src/...`
e roda via `utest .`; quem consome `iodb` como submodule
(ex.: `bot/`) precisa ter `utils`/`utest` como submodules irmaos de `iodb`
no mesmo nivel.
